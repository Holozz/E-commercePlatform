# 淘宝纸质笔记本 AI 工作流试卖方案 V1

编制日期：2026-11-11。交付状态：可据此拆分实施，未接入账号、未部署软件、未发生采购或发布。

## 1. 已确认资源与实施结论

- 用户准备以淘宝个人店试验，尚无可用卖家后台，开店由用户解决。
- 有 1688 国内站账号，无开发者权限、ERP 或现成业务系统。
- 商品为纸质笔记本；有部分线下货源，线上货源由系统寻找。
- 总试验资金低于 1 万元；可使用本地电脑，也可租服务器。
- 目标尽可能自动化；初期涉及钱款由人监督；有人员完成实物检查与异常处理。

主路线：淘宝个人店 + 1688 代发 + 平台现成交易工具 + 自建 AI 工作台。先验证可用的代发和数据接入路径，再开发实际适配器。线下货源保留为对照报价及备用渠道；未具备稳定库存/代发条件前，不让它承担自动履约。

不以直接取得淘宝自研订单接口为前提。公开官方文档中的“商家后台系统”路径有天猫、公司主体及软件等准入要求，不能把它当作普通个人店的通用接口通道。[S1]

## 2. 试验规模与经营假设

这些是系统容量和试卖设计，不是订单预测或行业平均值。

| 项目 | 初始安排 |
|---|---|
| 店铺 | 1 家淘宝个人店 |
| 货源候选 | 首轮目标 30 个商品、约 5 家供应商，不凑数量 |
| 样品 | 约 3 家供应商、6–10 款，依据运费和报价缩减 |
| 首次上架 | 3–5 款、总计不超过 15 个 SKU |
| 扩展容量 | 100 个 SKU、每日 50 单、每日 200 条客服消息 |
| 履约 | 首选已验样供应商一件代发；不提前大量囤货 |
| 试卖周期 | 上线后先观察 30 天，低单量时不据此宣称市场已验证 |

先比较三种产品方向：A5 简约横线本、B5 学习记录本、同供应商现成多本装。第一轮暂不做定制印刷与自创混合套装。纸本单价较低，必须比较含运费成本；“多本装”只是待验证方向，不预设一定更赚钱。

关键规格：实际毫米尺寸、内页张数/页数、纸张克重、内页类型、装订、封面材质、单本重量、单包本数和可选颜色。页数口径不明时不直接按“张数 × 2”补值；“不洇墨”“可完全平摊”等须有样品依据。

## 3. 接入路径与第一道验收

### 路径 A：淘宝/1688 现成代发能力，优先验证

官方帮助文档描述了规格关联、自动生成待付款采购单、付款后上游代发以及物流同步。文档明确自动下单与自动付款不同。[S2]

操作：用户完成卖家后台开通与登录 → 检查 1688 代发入口 → 选择经核验的商品 → 绑定 SKU → 检查自动下单配置 → 验证采购单和物流回传。

这些能力是否仍在当前个人店开放、选定供应商是否支持，必须在真实后台确认。不得仅凭帮助文档承诺开通成功。

### 路径 B：服务市场的铺货/代发工具

若 A 不可用或能力不足，评估店管家、智能店长等候选的对应淘宝版本。两家公开页面提供铺货或代发说明，但不同平台版本能力不同，尚未验证个人店适用性、价格以及可供自建系统调用的接口。[S3][S4]

购买前逐条核实：

1. 支持当前淘宝个人店和 1688 账号绑定。
2. 支持所选供应商及 SKU，能生成待付款采购单。
3. 支持密文收件信息和物流回传，不依赖人工复制地址。
4. 可关闭免密支付；不会自动替换未经验样的货源。
5. 有订单状态、失败原因和导出/回调/API 能力说明。
6. 明确订阅价、接口额外费用与试用期。
7. 明确客服能力是否另购，以及是否真的支持接入自定义 AI。

“工具能自动下单”不代表“工具对我们的系统开放 API”。无 API 时可让工具独立负责交易，AI 工作台只在已有可读通道内做辅助；必须如实展示中间的人工同步。

### 接入失败时的选择

可用且允许的固定后台页面可评估本地浏览器执行器；登录、验证码和页面变动转人工，不绕过平台验证。不将浏览器点击付款作为首期实现。

如果 A、B 均无法提供持续订单同步和代发能力，停止交易适配开发并记录阻塞原因。可以先运行商品与核价工作台，但它不算自动营业闭环。不开多个平台分散接入成本。

## 4. 系统如何自己找货源

找货源不要求用户先提供链接；系统需要可用的数据获取工具，而非只调用聊天模型。

1. 每天生成有限的检索任务，例如“A5 横线本 现货 一件代发”“B5 记录本 纸张克重”“记事本 两本装 代发”。
2. 通过搜索服务获取公开候选页面；在用户本地已登录的 1688 页面或获授权商品工具中补全可见资料。具体自动访问方式以实际可用能力为准。
3. 保存来源 URL、时间和原始证据，去除重复商品，提取规格和供应商信息。
4. 缺少单件代发报价、运费、交期、包装与退货信息时生成询价草稿。首期草稿由人发送；只有另行明确授权收件对象和消息范围后才开自动询价。
5. 与线下货源同表核价，筛掉不满足基本条件的候选。
6. 输出待买样清单，人工批准采购和付款；实物验样后才允许加入履约白名单。

供应商门槛：现货规格明确、愿意代发、可验证发货能力、提供物流、同意素材使用、包装及退换责任明确。平台标识和宣传只能作为线索，不能代替验样。

## 5. 正常订单的自动执行路径

```text
检索任务 → 候选资料入库 → AI 提取规格 → 确定性核价
→ 询价/验样 → 加入商品和供应商白名单
→ AI 文案 → 字段检查 → 初次审核 → 发布并核实可售
→ 买家真实付款 → 订单同步 → 关联供应商 SKU
→ 生成待付款采购单 → 人工核对并付款
→ 供应商发货 → 真实物流回传 → 客户状态答复
→ 结算/退款对账 → 日报与异常任务
```

交易工具和自建工作台必须指定唯一的下单执行方。如果原生代发已经自动采购，自建执行器只能查询和审核，不能再发起第二笔采购。

每个节点保存输入、结果、外部订单号和下一步状态。重启后可恢复；写入超时先查询结果再重试。销售取消、部分发货和退款不会被简单当成完整新单处理。

有自动化权限且事实充分时：自动整理、核价、生成文案、同步状态、物流回填、日报，以及白名单内标准问答。首期付款、付费服务订购、广告开支、退款赔偿由人工监督。首次上架和新供应商样品需人工核实；以后可按已批准规格及内容规则减少审核。

常规客服自动发送依赖平台/服务商消息能力；接入不可用时只生成草稿，并明确标注。AI 不猜测物流，不承诺未经确认的退款和到货日期。工作台的“规则允许”不等于外部通道已经可用。

## 6. 核价、授权与资金规则

单笔贡献利润 = 卖家应收收入 - 采购 - 物流包装 - 平台支付等变动费用 - 广告分摊 - 预计售后损失。缺失费用必须标记，不能当作零。实际结算与预计值分别保存。

拟定试验门槛：每单贡献利润不少于 5 元且贡献利润率不少于 20%。这是初始经营筛选参数，需结合样品与市场价格调整，不是市场可实现利润的承诺。

采购前重新检查价格、规格、订单有效性与供应商。报价异常、新 SKU、缺货替代均转人工，不允许 AI 为了完成订单自行换货。

付款界面展示供应商、关联销售单、数量、运费、合计及资金池余额。下列限制是拟定上线配置，不代表现在已授权扣款：

- 首期每次付款均人工确认；自动付款关闭。
- 初始采购预警：单笔超过 100 元或当日累计超过 500 元转人工复核；随着真实销量调整。
- 周转资金建议 3,000 元；已付款未结算、待付款占用与可用现金分别计算，不能用买家已付款金额直接代表可支配现金。
- 报价、数量或收款对象发生变化，原付款批准失效。
- 暂停入口可停止新增上架、下单和消息发送；已提交交易仍需核实处理。

## 8. 技术实施基线

自研部分采用 Python 单体服务（FastAPI）+ PostgreSQL + 简单管理页面 + 一个持久化任务执行器。模型、搜索和平台均通过明确适配器接入。选择 Python 是为了快速实现资料处理与任务编排，不涉及求职技术栈。

数据库任务表保存业务状态、重试时间和外部结果；第一期不增加独立消息中间件、多 Agent 或向量数据库。业务规模超出后依据瓶颈调整。

本地先运行；如需持续回调，再部署同一应用与数据库。没有所需接口时，不伪造适配器成功。演示模式与真实模式有醒目标识，真实写入默认关闭，按能力逐项启用。

核心数据：供应商、商品事实及证据、报价快照、样品记录、SKU 映射、发布版本、销售单、采购单、物流事件、客服草稿、批准记录、任务和资金占用。

核心页面：今日待办、找货源、核价、验样与白名单、商品发布、订单履约、客服、经营对账。每个页面显示最后同步时间和数据来源。

模型只做提取、匹配建议、文案与回复；金额用精确小数计算。提示词输出 JSON 经结构和事实校验后入库。页面、商品描述和客户消息中的指令不得改变系统规则。

密钥由服务端保管；日志去除客户敏感字段；默认不给模型收件地址和电话。个人后台仅限授权访问，云部署启用 HTTPS；每日备份并在上线前验证一次恢复。平台要求的数据流向和部署条件优先于本方案。

## 9. 开发任务与验收顺序

工程工作量暂估 10–15 个开发工作日，不含开店审核、供应商等待、样品运输和经营观察；接口不可用时不承诺期限。

| 任务 | 产物 | 验收 |
|---|---|---|
| T01 账号能力核验 | 原生代发/工具能力表 | 真实后台确认支持当前个人店；无权限即记录阻塞 |
| T02 货源发现 | 检索任务、候选和证据保存 | 系统能找到新线索；不依赖用户预先给链接；缺字段不编造 |
| T03 商品标准化 | 规格提取和报价表 | 正确区分页/张、单本/多本、尺寸和阶梯价 |
| T04 核价与验样 | 成本计算、样品任务、白名单 | 运费未知不自动定价；未验样不进入履约 |
| T05 发布草稿 | 文案、字段校验与版本审核 | 只含真实属性；真实发布后查到对应状态 |
| T06 订单接入 | 同步或交易工具联动 | 重复/乱序事件不导致重复采购；有周期补漏 |
| T07 采购监督 | 待付款视图及结果核对 | 超时但实际成功时不重复下单；批准绑定具体金额 |
| T08 物流与取消 | 物流同步、异常和取消处理 | 支持部分发货；取消和采购状态冲突可人工接管 |
| T09 客服 | 事实检索、草稿和可选发送通道 | 规格与订单正确；退款等升级；通道未接入不报发送成功 |
| T10 日报及对账 | 预计/实际利润、资金占用 | 退款及平台费用纳入；发现未匹配款项 |
| T11 稳定性 | 重启恢复、暂停、备份 | 掉线与授权失效可恢复，外部写操作不会盲目重试 |
| T12 小范围试卖 | 3–5 款真实经营 | 真实订单有完整链路，失败可见；无订单时只报告技术验证 |

T01 与货源资料模块可独立推进；T06–T09 的真实适配取决于 T01，不能靠 mock 宣称完成。先做无资金副作用的回放/沙箱验证，再做必要的真实样品采购和正常试卖；不用虚假成交或评价制造测试订单。

系统验收与经营验收分开：系统能处理订单不代表店铺能获客盈利。首轮自然曝光与可控推广用于验证需求；不得在无曝光或极少样本时声称产品成功/失败。

## 10. 当前需用户完成的两项外部准备

1. 开通淘宝个人店并能进入千牛卖家后台，按页面要求完成主体、类目等资料。
2. 在自己的设备上登录淘宝和 1688；后续在官方页面完成必要授权，不在聊天中提交密码或密钥。

线下货源不要求提供链接；以后可录入照片、纸张规格和报价作为对照。线上发现由系统承担。

目前没有可操作的登录会话与账号权限，因此无法确认代发入口、实时报价、工具订阅价或可用客服通道。上述方案与公开线索已完成；开发、登录验证、验样、部署和真实交易尚未完成。
