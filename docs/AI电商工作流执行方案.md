# AI 电商工作流执行方案

状态：V0 通用设计底稿。已由《淘宝纸质笔记本试卖执行方案-V1.md》收敛经营范围和接入路线；冲突时以 V1 为准。尚未接入店铺或执行任何商业操作。

## 1. 目标与当前边界

目标是让商品、报价、上架、订单、采购、物流及客服形成持续执行的闭环。正常任务由程序执行；缺数据、超额度、状态冲突或平台不支持的操作进入人工任务箱。

第一阶段只接一个销售店铺、一种履约方式和一组供应商。平台与技术栈在资源确认后决定，不预设必须自研整个 ERP。

当前目录为空，尚无可复用的应用。待确认：店铺及站点、品类、供应商与代发协议、接口权限、现有工具、规模、预算、部署环境、人工值守和自动化授权范围。

## 2. 接入方式决策

每个环节分别确认读写权限，不能用“有开放平台”代替“当前账号能调用”。

| 已有资源 | 优先执行方式 | 需要验证 |
|---|---|---|
| 已有 ERP 且支持所需接口 | 保留 ERP 管订单与库存，增加 AI 和工作流层 | 读写能力、授权、费用、回调与调用限制 |
| 店铺及官方 API 可用 | 直接接官方 API | 实际拉取商品和订单、受控写入、结果查询 |
| 只有卖家后台和导出文件 | 导入导出运行辅助流程 | 导出字段、更新频率、人工交接责任 |
| 接口不足，页面操作允许自动化 | 对少量固定页面评估浏览器自动化 | 登录维持、页面稳定性、失败接管和结果核对 |
| 尚无店铺或供应商 | 先验证经营与履约条件 | 开店、供应商合作、样品、物流和试卖资金 |

仅靠人工导出文件的版本属于半自动系统，不能宣称已经实现无人值守同步。接口受阻时，要明确受阻节点，不用模拟接口冒充真实接入。

## 3. 工作流清单

### W1 商品发现、资料整理与候选筛选

- 触发：新增货源、导入商品表或约定的定时任务。
- 程序：保存原始资料、来源和采集时间，按供应商商品 ID/SKU 去重。
- AI：提取规格、分类、识别缺失属性；分析已有评论和需求证据。
- 程序：根据预算、成本、重量、交期等明确条件过滤。
- 输出：候选商品及依据、待询价事项、待验样任务。
- 人工：决定类目、确认样品和供应商承诺。缺少市场数据时不能生成可信的销量预测。

### W2 同款匹配、报价更新与核价

- 触发：新增候选商品、供应商报价变化或报价超过有效期。
- AI：提出候选同款关系，指出材质、尺寸、数量和版本差异。
- 程序：仅对已确认规格统一计价单位，计算运费、平台费用与贡献利润。
- 输出：可执行的供应商 SKU 映射、价格建议和计算明细。
- 异常：关键规格或费用缺失、优惠资格不明确、报价过期，暂停自动采购或调价。
- 复核：执行采购前重新检查该 SKU 的可采购数量、最新报价及交期。

### W3 商品内容生成与发布

- 触发：选品已批准且必填资料齐全。
- AI：生成标题、卖点、属性和图片文案，只依据已确认事实。
- 程序：校验平台字段、素材权限记录、SKU、价格与库存。
- 第一阶段：人工批准具体内容版本后发布。
- 发布后：查询平台处理结果，区分已提交、已受理、可售和发布失败。
- 异常：类目资质缺失、平台拒绝或内容冲突，创建人工任务。

### W4 销售订单同步与履约准备

- 触发：订单回调，或在平台限额内增量查询；另做周期对账补漏。
- 程序：校验事件来源，按平台、店铺和订单 ID 去重；查询当前支付、取消及退款状态。
- 程序：校验销售 SKU 到内部 SKU、供应商 SKU 的映射；检查可用库存或代发能力。
- AI：仅处理备注含义和异常分类，不决定是否付款或选用未经确认的替代 SKU。
- 输出：自有仓的待发货任务，或代发场景的采购草稿。
- 异常：缺货、地址不可处理、规格不明、订单取消、利润低于阈值，进入人工任务箱。

### W5 采购下单与付款

- 第一阶段默认人工审核采购草稿并付款。
- 自动下单开放条件：用户明确授权、供应商及 SKU 在白名单内、报价有效、预算充足、订单状态有效。
- 程序在执行前检查单笔/每日额度，并占用相应预算，避免并发超额。
- 下单与付款分别记录状态，付款自动化需独立授权和可用支付能力。
- 提交超时进入“结果未知”：优先查供应商订单或支付流水，确认未成功后才能重试。
- 每个销售订单行的履约关联必须可追溯；拆单、部分采购与退款不能简单重建整单。

### W6 发货、物流与售后

- 触发：供应商发货回调或定时查询。
- 程序：关联真实物流记录、核对包裹与订单行，在平台支持时回填发货信息。
- 程序：发现超时未发货、物流停滞或回填失败，创建待处理任务。
- AI：总结问题并起草催货、客户解释和售后回复。
- 人工：处理错发、损坏、缺货替代、赔偿及退款。
- 退款、退货与采购取消分别跟踪；不能认为销售退款会自动撤销供应商采购。

### W7 客服

- 触发：平台支持的消息接口，或人工提交待回复消息。
- 程序：查询商品事实、最新订单和有效售后政策，仅向模型提供必要字段。
- AI：分类问题、引用依据、生成回复及转人工原因。
- 第一阶段：草稿审核后发送；验证后仅开放已授权的低风险问答自动发送。
- 禁止仅凭模型自报“高置信度”决定发送。按问题类型、事实完整性、模板覆盖和评测结果控制。
- 退款、赔偿、地址变更、冲突信息及无法判断的问题转人工。
- 平台没有消息读取或发送权限时，客服节点明确降级为草稿辅助。

### W8 经营对账与规则调整

- 触发：每日汇总及平台结算资料到达。
- 程序：核对订单、采购、费用、退款与结算，分开显示预计和实际利润。
- AI：总结异常、退货原因及待验证改进建议。
- 输出：待处理事项与经营日报。费用缺失时标记统计不完整。
- 调价、补货和停卖建议按独立授权规则执行，不因日报建议直接产生采购。

## 4. 执行机制

业务状态和任务执行状态分开保存。每个执行任务保存业务对象、输入版本、动作、幂等键、尝试记录、外部结果 ID 和错误原因。

任务状态：待执行 → 待审核（按需）→ 已批准 → 执行中 → 成功/失败/结果未知/已取消。

审核绑定具体操作内容、金额、数量和有效期。价格、SKU、数量、客户要求等关键输入改变时，原批准失效。所有外部写操作执行前重新核对业务状态。

可重试的读取失败使用有上限的退避重试；外部写操作先确认是否已成功。平台不提供幂等能力时，通过业务映射、串行提交和结果查询降低重复风险，不能承诺网络条件下绝对“只执行一次”。

必须有暂停某个工作流或店铺的入口。暂停阻止新的外部动作，已提交动作仍需查询核对，不能假设暂停等于撤销。

## 5. 最小系统组成

1. 管理页面：候选商品、核价、发布、订单、客服、人工任务箱。
2. 业务服务与数据库：维护商品事实、映射、订单及任务状态。
3. 定时任务/执行器：持久化任务、重试、补漏与恢复。
4. AI 调用模块：结构化输入输出校验、版本记录、调用费用控制。
5. 接入模块：按实际资源接平台、ERP、供应商及物流。

优先使用已有 ERP 的确定性交易能力；仅对缺口自研。没有现成系统时采用单体服务和一个数据库，不默认引入多 Agent、微服务或向量数据库。

密钥与平台授权令牌由服务端保管，不放入提示词或普通日志。客户姓名、电话和地址不进入不需要这些字段的 AI 任务；系统保存必要数据并限制访问。持续运行前配置备份，并实际验证恢复。

## 6. 实施阶段与验收门槛

| 阶段 | 交付 | 进入下一阶段的条件 |
|---|---|---|
| 0 资源和授权确认 | 平台、供应商、履约、成本、部署与授权清单 | 每个关键操作明确谁执行、用什么接口、缺什么权限 |
| 1 接入验证 | 真实商品/报价/订单读取；独立验证发布和履约写入路径 | 证实关键接口可用，或明确接受的人工替代流程 |
| 2 内部运行 | 商品整理、确定性核价、AI 草稿、任务状态和人工任务箱 | 真实样本可处理；缺数据不虚构；重复订单不重复建采购任务 |
| 3 小范围营业试跑 | 用户批准范围内的发布、订单处理、采购及物流 | 外部结果可核实，异常有人接管，销售和采购可对账 |
| 4 受控自动化 | 逐项开放已授权动作 | 对应场景验证通过，设置额度与停止条件，能暂停并恢复 |
| 5 扩大范围 | 增加 SKU、供应商或平台 | 原流程稳定且可追溯，人工异常处理能力匹配业务规模 |

接入审核与供应商协商耗时单列，不承诺固定天数就能上线。资源确认后补充开发工作量、费用与具体交付顺序。

必须验证的异常：重复通知、取消后仍收到旧通知、采购超时但实际成功、供应商涨价/缺货、部分发货、退款与采购交错、授权失效、AI 输出非法字段、服务重启后恢复。

## 7. 待填写的自动化授权矩阵

下表是保守的初始设计，并非用户已作出的最终授权。

| 动作 | 初始方式 | 自动执行前需要的具体条件 |
|---|---|---|
| 读取已授权店铺数据 | 自动 | 明确数据范围及同步频率 |
| AI 整理与草稿生成 | 自动 | 数据范围、单次与每日调用预算 |
| 上架 | 人工审核后执行 | 类目/SKU 白名单、素材、最低价格 |
| 改价 | 建议 | 最低利润、价格上下限、频率及最大变动幅度 |
| 采购下单 | 人工审核后执行 | 供应商/SKU 白名单、单笔与每日限额 |
| 付款 | 人工 | 独立授权、支付能力、收款对象及额度 |
| 发货信息回填 | 验证后开放 | 真实发货证据、订单与包裹映射 |
| 客服发送 | 草稿 | 可自动回复的意图清单及转人工规则 |
| 退款/赔偿 | 人工 | 如需自动化，另行定义金额及适用条件 |
